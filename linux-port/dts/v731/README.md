# Linux v7.3.1 Samurai DTB inputs

This directory holds the production OS-facing wrapper for the standardized
Linux v7.3.1 build. It is applied inside the v7.3.1 source tree; the shared
SoC and board fragments are owned by
`linux-port/patches/v7.3.1/0001-arm64-add-standard-samurai-platform-glue.patch`,
while the camera/CCI/PM8008 stack is owned by
`linux-port/patches/v7.3.1/0002-arm64-standardize-samurai-camera-stack.patch`.

The wrapper deliberately:

- removes the source-tree debug `bootargs` and `stdout-path`;
- disables the EUD serial controller on the production USB port;
- switches the primary USB controller to the standard `snps,dwc3` binding with
  USB 2.0 peripheral mode;
- enables the standard DWC3 `tx-fifo-resize` property so bulk IN endpoints can
  use dynamic TX FIFO allocation;
- keeps the SuperSpeed/DisplayPort PHY disabled because this phone exposes only
  USB 2.0 on its Type-C connector.

The compiled artifact and all source/build/runtime hashes are recorded in
[`source-lock.json`](source-lock.json).
The `standard_rootfs_candidate` entry records the direct-rootfs Image, paired
boot/FAT, config and flash contract; it is deployed and runtime-verified.
The `tx_fifo_standard_rootfs_candidate` entry records the promoted DWC3
FIFO-resize pair, its ordinary-reboot runtime gate and its network tests.
The `uefi_standard_boot_candidate` entry records the offline
`\EFI\BOOT\BOOTAA64.EFI` -> GRUB -> Linux EFI stub chain, its paired
boot/FAT and rollback receipt; it is also **not flashed**.

The camera contract covers two CCI controllers, CAMSS, IMX471, IMX319,
S5K3M5, S5KGW1, the wide-camera LC898219XI lens and both PM8008 instances.
The kernel FAT DTB (`/samurai.dtb`) and the boot-embedded DTB FFS are kept
byte-identical to the built `sm8150-samurai.dtb`.

The `flash_led_v4l2_final` entry records the deployed additive PM8150L
rear-flash DTB and its paired boot/FAT. It uses the existing mainline
`leds-qcom-flash` driver and the standard LED-flash/V4L2-flash APIs. The
pair was written from the running Linux system, passed the DTB contract,
full runtime gate, 200 mA optical torch capture and an ordinary reboot.
External-power-removed cold boot and long thermal endurance remain open.

The `thin_private_layer_audit` source-lock entry is generated by
`linux-port/scripts/audit-thin-private-layer.py`. It inventories 14 C/H logic
files and 11 DTS/data files, finds no private ioctl/user-copy/Android entry
points, and records the 0004 patch that removes the non-UAPI MAX98937 and
AW8697 `status` sysfs attributes. The `thin_private_candidate` entry records
the independent Image/FAT pair built from that patch; the camera DTB and boot
carrier remain unchanged, the release has no dirty suffix, and the offline
verifier passes. It is not yet in the deployed Image and has no runtime
acceptance.

The `nfc_neard_candidate` entry records the standard NFC userspace path:
the mainline `nxp,nxp-nci-i2c` node is unchanged, while
`samurai-platform 5-r22` adds Alpine's `neard-openrc` service dependency.
The signed package, source hashes and offline verifier are recorded there;
installation, `nfc0` probing and a physical tag read remain open.
