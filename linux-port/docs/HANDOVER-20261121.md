## 设备卡 EDK2：结论与证据（最重要）

完整记录见 `BOOT-DTB-REGRESSION-20261121.md`。要点：

```
boot 现状  md5 c8088b065b59f29b84b816704ca61094  = boot-fixed.img（误刷）
boot 原版  md5 84476cf0d61cdb7358064ab9d154ec07  = boot-cur.img
logdump    sha256 56c8379b…  = logdump-candidate-20261120.img（11-20 已验证能启动）
```

两份 boot 逐文件比对：外层 3 个文件差 1（FVMAIN 容器）、内层 101 个差 1（DTB）。
固件/BootShim/BdsDxe/UiApp/SMBIOS 全部逐字节相同。

设备 DTB 与原版 DTB 的实质差异：

- `typec@1500` 由 `okay` 变成 `disabled`，`connector` 整个节点消失
- `usb@a600000` 由 `dr_mode="otg"` + `usb-role-switch` 变成 `peripheral`
- `s5kgw1` 的 `flash-leds` 消失
- 多出一个 `ethernet@20000`（disabled）

为什么会这样：内核树 `pm8150b.dtsi` 的 typec 默认 `disabled`，而
`sm8150-samurai-common.dtsi` 没有 typec/usb 的 board overlay；用这棵源码树
整份重编 DTS 必然丢这些描述。原版可启动 DTB 是历史会话逐点打补丁出来的。

然后重启，从 Wi-Fi 或 NCM 进 SSH。若仍不行，换
`logdump-live-20261120.img`（sha256 `125436109e7b…`）对照。

## 坑（别再踩）

1. **不要**用“当前源码树整份重编 DTB”去刷 boot。要做定点修改，必须从
   `boot-cur.img` 提取原版 DTB，保证其余 100 个 FFS 文件逐字节不变，
   再用 `patch-boot-dtb.py` 的布局算法（已自检过“同一 DTB 重建逐字节一致”）。
2. **不要**把 `boot-fixed.img` 当成“只删了 flash-leds”。它是另一棵树的产物。
3. `apk --root` 解析本地仓库会失败，离线验收必须 `chroot`。
4. 板级包重编后必须核对 `lib/apk/db/installed` 里的版本，不能只看文件是否覆盖。
5. `noarch` 的板级包在索引里必须记成 `aarch64`，否则设备解析不到。
