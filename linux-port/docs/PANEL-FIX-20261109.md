# RMX1931 panel wake candidate (superseded)

Status: superseded, never flashed. The 2026-11-10 HBM investigation showed
that this candidate addressed a first-frame timing hypothesis rather than
the physical root cause.

> **Validity note.** This is not the fix that made the panel work. The
> SOFEF03F brightness space crosses into HBM at 1024; the old driver wrote
> `0x51=1024` without the `0x53=0xe0` HBM entry, so the panel stayed black
> even though DPMS and backlight reported on. The bounded reapply below was
> built as a diagnostic candidate, not deployed, and must not be presented
> as a working remedy. See [PANEL-HBM-20261110](PANEL-HBM-20261110.md).
> For new builds use the consolidated
> [`0010`](../patches/v7.3.1/0010-arm64-panel-sofef03f-hbm-first-frame-consolidated.patch)
> patch; do not stack `0003`/`0005`/`0009`.

This candidate replaces only the kernel FAT `/Image`; the boot carrier and
DTB are unchanged. It adds a bounded standard backlight reapply in the
SOFEF03F panel driver after the first-frame gate opens.

## Historical install procedure (do not use)

This procedure is retained only to explain the earlier diagnostic build. Do
not flash it: it does not contain the HBM transition and will not fix a 1024
brightness black screen. Use the deployed `0009` or consolidated `0010`
instead.

```sh
scp kernel-fat-panel-fix.img root@PHONE:/tmp/
scp flash-kernel-linux.sh root@PHONE:/tmp/
ssh root@PHONE
sh /tmp/flash-kernel-linux.sh \
  --kernel-fat /tmp/kernel-fat-panel-fix.img \
  --sha256 b7f55d165ce396e82fb1307f697c48517cd008920486f1a6b89f4c2074ac5c2d \
  --reboot
```

The helper resolves GPT label `logdump`, verifies size and hash, refuses a
mounted or read-only target, writes, and reads the partition back.
