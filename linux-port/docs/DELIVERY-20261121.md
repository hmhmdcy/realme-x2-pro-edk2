## 本轮修掉的四个真实缺陷

### 1. 板级包版本落后于配方，`apk upgrade` 永远无事可做

交付镜像记录的是旧版本，而配方已经前进了：

| 包 | 镜像里（改前） | 配方 | 镜像里（改后） |
|---|---|---|---|
| `samurai-platform` | 6-r22 | 6-r25 | **6-r25** |
| `samurai-platform-pulse` | 6-r21 | — | **6-r25** |
| `samurai-ssc` | 1-r2 | 1-r3 | **1-r3** |
| `samurai-systemd` | 1-r4 | 1-r5 | **1-r5** |

之前的重建脚本只是用 `install -m` 把脚本覆盖到镜像里，**从不更新
`lib/apk/db/installed`**。于是文件是新的、数据库是旧的：

- `apk upgrade` 认为已安装的就是最新版，什么也不做；
- `apk verify`、`apk audit` 与配方对不上；
- 一旦真升级，apk 会用**旧包的文件清单**替换，反而把新文件删掉。

现在 `repack-embeddings.sh` 会先跑 `boardrepo-sync.sh`，再按路径
`apk add` 三个包（含子包），最后用数据库核对版本，不一致就中止。

### 2. 板级索引在 `--root` 下解析不到

`apk --root <dir>` 把仓库路径当作**宿主机**路径解析。镜像内的板级仓库
`/usr/share/samurai/packages` 在主机的根下并不存在，所以每次都会打印

```
WARNING: opening /usr/share/samurai/packages/aarch64/APKINDEX.tar.gz:
    No such file or directory
```

设备上 apk 运行在自己的 root 里，不存在这个问题。**离线验收因此必须
用 `chroot`**，不能用 `--root` 来判定板级仓库是否可用。本轮验收脚本
已改成 chroot，结果为 `OK: 2950.3 MiB in 1254 packages`、`rc=0`。

### 3. `noarch` 包放进 `aarch64/` 仓库会“索引里有、文件找不到”

配方写 `arch=noarch`，abuild 产出的 APK 也记为 `noarch`；但仓库目录是
`aarch64/`。apk 按 `aarch64` 拼路径，于是报

```
ERROR: samurai-platform-6-r25: package mentioned in index not found
```

`noarch` 在 abuild 语义里只是“构建不依赖架构”，产物仍属于设备架构。
`build-board-packages.sh` 现在把 `noarch`/`all` 统一记为 `aarch64`。

### 4. `/etc/unudhcpd.conf` 与官方 `postmarketos-initramfs` 抢同一个文件

冲突原文：

```
ERROR: samurai-platform-6-r25: trying to overwrite etc/unudhcpd.conf
       owned by postmarketos-initramfs-3.11.0-r1
```

该文件注释里明确写着“这是 initramfs 使用的配置，不是给 unudhcpd 直接读的”。
板级地址已经由两处覆盖，不需要再动这个文件：

- systemd：`samurai-systemd/10-samurai-unudhcpd.conf` drop-in
  （`UNUDHCPD_SERVER=172.16.42.1` / `UNUDHCPD_CLIENT=172.16.42.2`）
- OpenRC：`/etc/conf.d/unudhcpd`

因此已从 `samurai-platform` 的 `source`/`package()`/`sha512sums` 中
移除 `etc_unudhcpd.conf`，文件本身保留在配方目录作为历史参考。

## 相机 flash 模块

基线镜像里的运行内核目录仍是 stub 版：

| 文件 | 基线 | 交付镜像 |
|---|---|---|
| `leds-qcom-flash.ko` | 18 KB（无 `v4l2_flash` 符号） | 104,824 B |
| `led-class-flash.ko` | 16 KB | 69,736 B |
| `v4l2-flash-led-class.ko` | **缺失** | 90,824 B |

三个模块的 vermagic 均为
`7.3.1-rmx1931-samurai-v731-usbwake-otg SMP preempt mod_unload aarch64`，
`nm -u` 可见 `U v4l2_flash_init` / `U v4l2_flash_release`。

重建脚本现在会从内核树重新植入这三个文件；缺失即中止，避免再次
静默退回 stub。
