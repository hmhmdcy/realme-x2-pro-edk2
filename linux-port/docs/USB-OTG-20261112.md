## Boot guard

为允许无人值守部署，rootfs 增加了 one-shot `samurai-boot-guard`：

- 只有 rootfs 写入 `armed` 标记后才工作；
- 下一 boot 若 600 秒内没有通过 SSH 执行 `confirm`，就把事先校验
  的 boot/logdump 回滚镜像写回并重启；
- 回滚镜像大小、SHA-256、分区可写和未挂载状态均在启动和写入前
  复查；
- 本次回滚目标是部署前 boot `69cf8066...` / logdump
  `767b7985...`；
- 两次 smoke/正式部署都在恢复 SSH 后 confirm，marker 已清除，
  `samurai-boot-guard` 当前 idle；
- 超时回滚的写回顺序已改为先 `logdump`、后 `boot`，使最后一个
  关键启动镜像写入成功后仍保持成对一致；
- guard 仅作为 `linux-port/diagnostics/` 的无人值守运维工具安装，
  尚未并入 `samurai-platform` APKBUILD；普通生产运行不依赖它；
- `test-samurai-boot-guard.sh` 用临时文件验证 60 秒超时后的
  `logdump→boot` 写回顺序，不接触真实块设备或重启主机。

## 只读门禁

运行态只读快照：

不绑定/解绑 gadget。部署前曾在 gadget-only 手机上做负向对照，
按预期报出 12 项缺失，未执行任何写操作。证据：

```text

  negative-control-current-gadget.txt

```

连接 OTG 设备后的只读 host 探针：

```sh
linux-port/scripts/test-usb-otg-host.sh --storage --hid \
  --require-typec-data-role
# passive OTG data + phone-sourced VBUS test:
linux-port/scripts/test-usb-otg-host.sh --storage \
  --require-typec-data-role --require-vbus-source
```

它只枚举 `usb_role`、Type-C power/data role、xHCI root hub、USB
sysfs、`lsusb` 和 `lsblk`，不挂载 U 盘、不切换角色。
`--require-typec-data-role` 要求 TCPM data role 为 active `[host]`；
`--require-vbus-source` 进一步要求 active `[source]`，且
`/sys/class/regulator/*` 中名称为 `usb_vbus` 的 regulator 处于
`enabled`，防止只切换 TCPM 角色而没有实际打开 PM8150B VBUS boost。
两者都不是 synthetic URS 能替代的。
部署前的 gadget-only 手机上按预期报出 host role、xHCI 和 root hub
缺失。fake-sysfs 正/负对照
`linux-port/diagnostics/test-usb-otg-host-vbus-role.sh` 已离线通过：
`host [device]`/`source [sink]` 普通模式通过但强制 TCPM host 和
VBUS source 失败，`[host] device`/`[source] sink` 强制模式通过；
新增的“`[source]` 但 `usb_vbus=disabled`”负向用例也会失败。
