Reviewed `device.py` SHA `169a2e238e07bcb0b430f848b7595a0d8ff1ff1ddf30eb5c071b5ec3fdf52647`, `controller.py` SHA `51076c08735096458c7f91730ef464db50223cf75ddb70730f12e4ca652ac923`, protocol SHA `e7e1209477e3879b05fd39891dc6a5ffabf3e725bf80ad6e5cc48de63a8f282e` and gates SHA `0206d2c0a5c85cdc5d9796ba9b6326a85b9b4708af2fe9eb7b671b9eb434e415`. The author's 35-boundary receipt is reused; no generator, author suite, earlier helper twelve groups or icon matrix was run here.

One concrete completion gap was identified during review and fixed by the author before freeze: if zero-write close-expired successfully unloaded the module but its reply/last cleanup became unknown, the original absent-module qualification only accepted committed state. A timeout has no commit receipt, so that path could not release its remaining owner despite known module absence. The current source accepts an exact retained close-zero-write intent with original terminal unload-process evidence, observer cleanup and unchanged environment, then qualifies close-expired for owner-only completion. It still rejects different instance or attempted/unknown writes.

`test-absent-expiry.py` runs the actual current qualification, recovery proof and execute functions against a temporary filesystem and explicit identity/process/sysfs boundaries. It verifies a wrong-instance absent-expiry receipt is rejected; a same-instance unknown close after successful unload qualifies and finishes by releasing the owner. Any helper read, control write, observer stop or module command in that absent completion path is a test failure. The original unload-process receipt remains the only one. `absent-expiry-result.json` records these new targeted cases and exact tested source bytes; copied `tested-*` files preserve those bytes. This is not a complete hardware or transport simulation.

The remaining requested paths were read statically against the author's pinned receipt:

- Only launch, arm, finish and close-expired are mutating. Host status/fetch errors write read-error evidence without creating/replacing the unknown-mutation marker; device status errors also remain read-only. A failed read therefore permits another read of the same transaction.
- Local mutation intents are exclusive-create, including a distinct qualified-recovery intent. A second invocation with the same qualification collides before SSH. Unknown arm cannot rearm or relaunch; qualification requires explicit reviewed terminal evidence.
- Qualification verifies all original mutation processes are absent/zombie with exact process receipts, an exact terminal observer and retained transaction/token/instance. It pins both host unknown bytes and remote uncertainty bytes, with a bounded BOOTTIME age rechecked before cleanup. A live or reused/unknown process blocks cleanup.
- Present verified state performs explicit commit once; present committed state skips commit. A helper absent after an original unload requires exact retained committed or close-zero-write evidence and terminal process proof. The qualified absent completion checks absence again and performs neither commit nor rmmod. It does not replay a previous transaction.
- Exact old-bit-zero verified state remains an explicit adoption/commit case; it is not confused with an attempted write. The parser/readiness gates keep initialization, physical cycle, charging telemetry/CV, observer timing and UI events distinct. A stale helper/status gate or low remaining arm time cannot authorize a user prompt.

No additional blocker was found in this limited completion/readiness scope after the author's close-expired fix. This is not a proof of physical 0x1358 behavior, all possible OS failures, module lifetime races or network recovery. No author file, phone, SSH, USB, SDK or shared kernel source was modified or accessed.
