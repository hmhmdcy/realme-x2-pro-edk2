# WARM/COLD Full exit with fresh SOC — offline candidate

This independent three-file patch is based on the frozen `97c` charger source (`1c088829…e5b4b1`) and the R8 internal headers. It fills one specific OEM gap: `oplus_chg_check_tbatt_is_good()` changes temperature status, and **only when the previous status was WARM/COLD, SOC differs from 100, `batt_full` is true and `charging_state==FULL`**, it removes the FULL voter. It then updates the temperature status/setters. The fixed source is commit `23172a1571bd91156032cc9fef16284a82b63d2c`, lines 4319–4328. Other temperature changes do not satisfy this branch. Source hashes, exact function ranges and SOC mapping are in `source-evidence.json`; the existing temperature oracle is reused unchanged.

The normal online OEM data path assigns `chip->soc` from the gauge getter (5487), rather than `ui_soc`. That getter (1172–1204) reads `reg_soc`; its calibration bounds the integer to 0..100. The selector is 0x2c (1414/header 53); the FFA5 override changes only current selection. The installed Image502 `bq28z610` map also reads SOC at 0x2c, but its CAPACITY property returns a cache. This patch therefore adds one **read-only standard SMBus word** at 0x2c inside the existing gauge bus segment. Only a fresh successful word in 0..100 is known. A read error or out-of-range value is unknown, never cached, clamped or replaced with zero. This optional metadata cannot grant the new shortcut; existing mandatory gauge/current/MAC errors retain their original fatal behavior. OEM fallback/smoothed/UI/RTC SOC behavior is not imported.

The driver passes the actual thermal band before and after this step, fresh SOC, and previous successful Full holding to the existing Full helper. `full_state.band` is not used as a substitute for a current thermal edge, so INHIBIT cannot defer a crossing until AUTO returns. **The old `full_holding` flag alone is insufficient:** `sm_suspend()` stops hardware without clearing it. On an otherwise eligible edge the driver reads current REG08 and requires CHG_EN/INHIBIT bits (`0x18`) both clear. INHIBIT or an enabled charger disqualifies immediate release; read failure takes the existing I/O fault/stop path without clearing Full. The helper input `was_full_holding` is supplied with this edge-specific readback qualification by this driver.

Only existing Full + AUTO + complete current protection/policy + this WARM/COLD exit + known SOC 0..99 can emit one immediate recharge result. Existing latch, timeout, OCA/TCA, invalid source/sample, bad clock, forbidden recharge or an unsafe destination still wins. The result removes only the Full hold/cause and resets its incomplete streak; the unchanged policy and masked transaction remain the authority for enabling hardware. Limits, termination, safety, the inherited 4.3625V/250mA/900mA ceilings, and actual USB budget are unchanged. Unknown/100 SOC does not authorize **this new branch**; the independent original six-low-voltage/5-second recharge path remains available. No delayed SOC permit is saved after a denied edge.

`test-result.json` records one successful host-only run: native exec `6d3d01`, GCC PID970 and test PID983 both waited to exit 0, ASan/UBSan/`-Werror`, 11 groups/91 assertions. It executes the actual extracted `sm_gauge_sample` and `sm_step_locked`, actual Full/policy/transaction helpers, and the frozen OEM temperature bodies. New cases cover the exact OEM condition, WARM/COLD exits, SOC 0/99/100/error/out-of-range, no stale SOC, ordinary band changes, manual INHIBIT, six low samples at the original cadence, old fault/timeout/TCA/OCA/I/O precedence, and a stale sleep-time Full flag with REG08 inhibited or unreadable. Hardware/file/clock boundaries are fakes. The old 97/20k/other matrices were not rerun; 37 matching existing function bodies and all old inputs remain unchanged.

This is worthwhile as a small source candidate, not a fix for the current NORMAL Full or a physical Full/recharge acceptance claim. There is no kernel object/module build, package, host tool, installation, parameter/default change, device access or thermal stimulus. The 97c source/package and current phone are untouched. A subsequent reviewed build and controlled warm/cold transition with fresh SOC evidence would still be required before adoption; dynamic cold-band CV changes retain the previously documented hardware-validation limit.
