# Same-boot charger update: icon capture profile

This source-only adapter accepts the original IRQ boot adoption (`5fca`) plus **one actual successful charger update fetch**. It keeps that adoption, boot, guard and global pointer, and overlays only the runtime manifest (`18e8`) and charger note (`fe15`). It does not create a new boot adoption, request an update, change charging controls, or modify the desktop.

`update-review.py::review_update(update_directory, base_review)` takes the **exact `fetch-<nonce>-private` directory returned by the frozen update host**, not its transaction root or a guessed latest fetch. It rechecks the original request/binding, fixed executed fetch and original SSH wait, worker/supervisor wait-zero chain, old/new disk tuple, inhibited boundaries, complete saved safety/source/limit samples, unchanged provider notes, and unchanged consumed MAC bytes plus held kernfs identity. The actual worker's health/continuity functions are reused. Their saved observation checks run at each recorded `read_end`; this is historical evidence, never a claim of present device freshness. Healthy Full preflight, a refused/failed update, unknown child, changed protection instance or incomplete final protection cannot produce overlay pins.

The collector worker, audit, entry, historical 32-case receipt and original finite `run`, ready, fetch and cleanup function bodies are unchanged. Only profile identity and the remote output directory change. Local adoption/overlay review finishes **before** the original timed SSH operation. Status/fetch retain the bound evidence and original launch marker; the prevalidated callback performs the fixed original-key `-C` SSH call without repeating local review. The original 8-second round-trip gate, two fresh heartbeat observations, 130-second ready reserve, 90-second reconnection observation and 300-second total deadline remain in effect.

Fourteen new affected cases passed (native session `1747`, terminal `fc6cec`, exit 0); three source-only defaults each completed their owned child wait with exit 0 (`c1ae72`). Old matrices were reused, not rerun. Two earlier failures remain in `history/`: a synthetic snapshot omitted `state.driver`, then the new collector loader failed to prefix a reference-relative source path with `REF`. The fixture and that one actual loader line were corrected respectively; protection policy was not relaxed. Temporary synthetic receipts/cache identities used by tests are not phone evidence.

Default checks: `python3 -B launcher.py`, `python3 -B bind-identity.py`, or `python3 -B update-review.py`. Only after a real managed update has passed and its originals were fetched, run `bind-identity.py --execute-bind --context <original-context> --camera <original-camera> --probe-directory <original-probe> --capture-directory <original-postboot> --update-directory <exact-update-fetch>`. Bind rejects missing/failed evidence before creating the pins directory. Then use the original explicit `launch → status → prompt only after ready → fetch` sequence with a fresh capture transaction. This leaf has not bound real runtime pins, launched a capture, or measured icon improvement. The current Full-only preflight is insufficient for this binding.
