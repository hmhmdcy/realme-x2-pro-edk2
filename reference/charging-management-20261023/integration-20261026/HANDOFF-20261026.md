## Why #513 exists

The #510 trial failed during `qcom,pmic-typec` probe because the early APSD/ADC
preflight sampled once while Type-C state still returned `-EAGAIN`. It also
showed that replacing `/etc/init.d/samurai-charging` without updating the main
manifest service hash makes the normal charging service fail verification.

#513 addresses both issues:

- APSD handoff uses a bounded 2 second retry at 20 ms intervals for transient
  `-EAGAIN`, `-ESTALE`, `-ENOLINK`, `-ENODATA`, `-ERANGE`, and `-ETIMEDOUT`.
- `realme,apsd-handoff-trial` is treated as a presence-only DT property.
- Stage backs up and transactionally patches the main manifest service pin.
- Stage failure and watchdog rollback restore the original main manifest and
  OpenRC wrapper before requesting reboot.
- The canonical host operator uses `-NoFetch`; postboot acceptance requires a
  same-boot guard readback of the actual boot and logdump partitions.
