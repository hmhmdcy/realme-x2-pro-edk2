The finding remains in `r1-stdin-eof-finding.json`; R1 source and receipts remain archived by the author.

R2 changes only `ssh_worker` and `terminal_job`. The original worker now attempts to close its still-open stdin before waiting that same Popen, without kill or retry. Wait, log flush/close/hash and terminal-publication errors are retained. The separate finalization record binds the original PID, exact stdin and terminal-file hash; missing/failed cleanup or publication cannot be promoted by `terminal_job`, even when the child returned zero. A close/wait failure does not prove the underlying process ended; it remains unknown and cannot authorize another mutator.

One retained R1 behaviour is important: **process-receipt capture failure does not necessarily prevent input transmission**. The worker still may call `communicate`; `receipt_error` then prevents terminal qualification. The action might have occurred, while its outcome remains unknown and its intent consumed. The exact request/input intent was durable before Popen. This is not described as “receipt failure never sends,” and no retry is introduced.

Requested argv, WSL-interoperability observed argv, input hash, same-child wait and output hashes remain distinct evidence. Unknown originals can be retained by status/fetch without replay.

It verifies the exact two-function delta, all unchanged outer source, remote/supervisor/pins and seven-raw export identity, plus the three new cleanup cases/current default-zero receipt.
