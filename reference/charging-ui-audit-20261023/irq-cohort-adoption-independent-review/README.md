# IRQ cohort adoption independent review

This review covers only the new adoption layer: exact #502/IRQ carrier binding, predecessor pointer, authenticated original postboot request, fresh raw audit, new guard, owned SSH child and pointer publication. The frozen host R2/device/operator evidence reviewers are reused; their old suites are not rerun. No author module, test, entry point, transport, device or build operation is executed by this review.

Within this scope no new blocker was found. `review()` first uses host R2's actual completion/stage/transport/raw-audit chain, then requires the exact new #502 boot, `eddadec…` boot carrier, retained `ace2…` logdump and cohort manifest. The descriptor retains the authenticated request object and raw postboot output digest. `postboot_request_sha256` is explicitly a sorted canonical-object digest; it is not the formatting-preserving hash of a separate request JSON file. Actual request authentication is inherited from the R2 executed-payload/stdin proof.

The device payload is the unchanged frozen collector prefix followed by the new tail. Its fresh complete audit, unchanged new UUID and #502 must pass before creating the unique new directory. Fresh proof is fsynced before the UUID guard; both directory levels and file readbacks are checked. Existing/partial directories remain consumed. This creates metadata only, without changing charging controls, USB policy or carriers.

The SSH process is owned from its sole Popen through input delivery, EOF/cleanup and same-child wait. Exact requested argv/input SHA and observed birth/cmdline are retained separately, including WSL interop cmdline differences. Receipt or partial-send failures cannot publish a pointer. Only a successful bound fresh reply permits publication; predecessor fields must match the authenticated original #502 adoption, and the current pointer must equal its retained original bytes at both checks. This relies on the documented exclusive owner window, not a general concurrent compare-and-swap. A failure after remote guard creation or pointer replacement can leave an unknown/unpublished state; the once directory is retained and no automatic retry is provided.

The author 20-case receipt and default/optimized entry receipts are hash-bound, with existing host authentication and fresh device IO explicitly fake. These establish source/metadata transaction boundaries only. There is no actual runtime request, guard, endpoint, adoption, boot success, IRQ physical delivery, charging latency acceptance or full rootfs recovery in this review.
