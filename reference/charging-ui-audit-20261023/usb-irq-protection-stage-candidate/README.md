# Disk-only stage worker for the USB IRQ/protection cohort

This is an offline candidate. No real stage request, device transaction, lease, guard or #502 adoption is generated here. The default `stage-worker.py --check-only` does not inspect a device or import the installed manager. Only `--execute-stage` reads the bounded request from stdin and enters the actual device path.

The worker accepts only the real frozen three-file payload `9dee06dd…4fb3c`, cohort delivery `3d5b78bc…2a07b` and new manifest `5fca8e5a…69417`. Its source pins are the exact R8 manager `61451ffe…55aa4`, OpenRC lifecycle, old R8 disk/module notes, Image502 `#502 SMP PREEMPT Tue Oct 20 03:03:47 UTC 2026`, original boot `97811cc4…7f695` and logdump `ace2e261…63ed1`. The independent host builder must first revalidate the full actual #502 postboot/adopt/current-pointer/strict-endpoint chain. It must refuse missing future evidence before creating a request. The schema and stable filenames are in `contract.json`.

## Actual ordering

The unique host transaction contains `stage-worker.py`; its `device-stage` subdirectory is created exclusively by the original worker. A durable local process receipt records that worker's PID, start ticks and argv. No child, `rc-service`, external command or service restart is started by this worker. The host owns the one detached dispatch and same-process status/fetch mechanism.

The worker checks the current boot, exact version/release, original SoC hashes, rootfs marker, actual adopted guard bytes/hash and the short explicit device-window lease. It reads the actual sibling `fresh-validation-private.json`, validates all nine completed #502 adoption checks and their identities/carriers/R8 notes, and records the actual proof hash. The host binds the already-recorded `postboot_raw_sha256`; it does not invent a digest for a proof it has not fetched. The collector's manifest text is known to be stripped: its original file-fact hash, not a hash of stripped text, identifies the exact disk bytes.

Under the original `/run/lock/samurai-charging.lock` flock, it freshly imports the exact installed manager, calls its `verify()` and compares all three old resident notes. The actual current boot/logdump partitions are streamed through O_RDONLY descriptors and hashed. The current R8 disk bytes/modes, startup500, ordinary protection, safe NORMAL-band telemetry, limits/CV, real SDP/CDP-classified budgets, camera idle state and four current session processes are checked. A valid existing Full hold is accepted only with complete Full fields, known cause, session zero, correct CHG-disabled readback and no old fault, timeout or TCA/OCA. It does not infer Full from capacity or change charging semantics.

Exact original three-file bytes are backed up with mode 0600, file fsync and directory fsync. With the original service lock already held, the worker directly calls freshly loaded `manager.command(old, 'stop')`; calling `rc-service` would reacquire that lock. The original manager synchronously requests INHIBIT and verifies REG08. A failed stop or failed fresh post-stop proof prevents any module/manifest replacement. This path does not read destructive REG14 or any new evidence command.

Each target is checked again against its exact original hash/mode. Replacement order is **USB ko → protection ko → manifest**. Every target uses a unique exclusive temporary, complete write, chmod0600, file fsync, rename, directory fsync and exact readback. Durable journal steps precede the operations. The live short lease is rechecked before each replacement and after final observation. There is no automatic rollback or retry, including when all three new byte sequences are visible but fsync or acceptance failed.

Final disk verification uses the new manifest. Live verification deliberately uses the **saved old ko bytes** and all three old resident notes. The new files are not loaded; DWC3 still owns the old native provider. INHIBIT, configuration limits, the source and the current camera/session state must remain correct. A successful result can only be `staged/runtime_pending`; it is not new runtime, an IRQ delivery result or a query result. Success requires all fields in `contract.json`, same-worker terminal evidence, exact three target hashes/modes and no receipt/close error. Cleanup errors are collected before the final result is published.

## Failure and later handoff

Every failure preserves its transaction, primary phase, atomic substage, all target old/new hashes and any retained temporary hash. Unknown or mixed files are not overwritten. The worker retains INHIBIT where the original stop succeeded and never issues AUTO, insmod/rmmod, boot/logdump writes, reboot, PM or MAC capture. Saved evidence and same PID/start ticks/argv are the only follow-up path; an exception or transport gap cannot authorize another dispatch.

A future reboot/handoff tool must independently support **new disk + old live + INHIBIT**. It must not invoke the old `loaded_matches(new path, old resident)` quiesce logic or reuse the prepared #502 notification restart context. A future postboot context must bind the original stage result/raw hash and `source_boot_id` and require a new boot. This worker neither constructs that context nor grants activation permission.

The new local tests execute the actual transaction, replacement, lease, adoption-proof and once-claim functions with fake OS/device/manager boundaries and the real cached forward/rollback payloads. They cover managed/Full and SDP/CDP, stop failures, each target's write/fsync/rename/directory-fsync failures, unknown target readback, mid-transaction lease expiry, final verify/cleanup failure, exact adoption and request rejection, and duplicate output refusal. The first Windows fake-path mismatch is preserved in `history/`; the fake filesystem alone was corrected to normalize host path separators. No old driver, IRQ, codec or module suite was rerun; no compilation, mount, SDK, SSH, USB or device action occurred.
