This is an offline, once-only capture adapter for the frozen observer module. It has not been bound, launched or used on a phone. Default `python3 -B host.py` checks frozen source inputs only. Actual completed IRQ-cohort postboot **and adoption**, current pointer and original-key endpoint are required before `bind` creates a transaction directory/request. Prepared Image502 or disk staging alone is insufficient.

The only device control is one `capture\n` store to the observer attribute, under `/run/lock/samurai-charging.lock`, after the cache reports `attempted=0`. The worker holds both original attribute file descriptors, checks their kernfs identities and bound platform instance, and brackets the operation with exact boot/guard/manifest/new disk protection ko/resident note checks. Existing module code performs the fixed batch under `p.lock -> I2C_LOCK_SEGMENT`; this tool does not issue raw I2C, reload a module, alter charging, stop a service or rearm an attempted instance.

`stage-worker.py`, `--execute-stage`, `stage-supervisor.py` and `device-stage` are retained names to reuse the original R2 supervisor byte for byte. Here the action is observation, with no file staging. The host delegates to the original R2 `transfer` function, including original key/options, launch intent, owned stdin EOF on publication failure, same-Popen `finally wait`, and status/fetch. `remote.py` differs at exactly four locations: transaction, request schema, IRQ adoption namespace, and removal of the unrelated three-file payload check. `prepare-sources.py` records this derivation. No new dispatcher is introduced.

Future root use, after actual IRQ adoption and independent review, from the same WSL environment as the original strict-key transport:

1. `python3 -B host.py --action bind --transaction protection-capture-<new-unique-name> --context <actual-context> --camera <actual-camera-proof> --probe-directory <actual-probe> --capture-directory <actual-postboot>`
2. In the coordinated exclusive window, `python3 -B host.py --action launch --transaction <same-tx> --window-confirmed`. This creates a fresh lease of at most 120 seconds; it permits starting the synchronous store, not forcibly interrupting kernel I2C.
3. `--action status` and `--action fetch` use that same transaction. An unknown launch is never repeated. Fetch after a changed boot preserves original bytes and reports source-boot-ended instead of attributing a reused PID. No timeout kills or lease renewals occur.

The original detached supervisor uses a fsynced regular request fd for the sole worker stdin and owns/waits that worker. Fetch retains all raw files first. Promotion requires exact request/raw hashes, the original worker and supervisor PID/startticks/argv/request chain and terminal0, matching identity brackets, an actually attempted terminal batch, and the store/batch BOOTTIME interval. EALREADY, unknown or unattempted stores cannot promote a cache. Known kernel errors can yield a source-authenticated failed batch only when the store errno matches the cached batch error; `sequence_complete` remains separate. Missing/unknown/nonzero process evidence or mismatched identity cannot promote the raw capture. No failed store is repeated.

Saved cache text is passed to the frozen `parse_saved` and existing decoder `58aa…10f2`. The actual C decoder rejects short/incorrect length, command echo and checksum claims. The outer receipt binds one raw report to the owned boot/instance/time; C validation alone cannot detect splicing equivalent valid frames from another identical family member. Parser `freshness_verified`, `boot_identity_verified`, compatibility, TCA classification and charge/recharge authorization remain false. Outer `source_authenticated` / `batch_time_bound` are narrower provenance facts. A complete batch is neither state stability nor new 2719 bit semantics nor physical acceptance.

The final 21 targeted cases execute the actual new worker functions and adapter gates with OS/hardware/authentication boundaries faked. Three use existing saved C-output fixtures through the original parser and existing pinned C executable, including short-transfer and wrong-identity cases. A fourth saved-path case runs the unchanged supervisor itself with a harmless local child and real Popen/wait0 receipts. The original worker terminal deliberately has no startticks: it is associated with the launch by request/boot/PID/argv/supervisor PID and the exact owned-wait source. Startticks are required on launch, worker process, supervisor process and supervisor terminal.

The original 21 observer / 26 parser / process-owner matrices were reused, not rerun. All test bytes/logs stay in the named private test output; no binary is added here. Initial 17-case sources/receipt are preserved in `history/initial-17`: their synthetic terminal mistakenly included startticks and hid this composition defect; they are not final acceptance. One later fixture-retention assertion failure is preserved separately. The final actual-supervisor test closes that wiring gap, without claiming a new concurrency proof of the entire process lifecycle.
