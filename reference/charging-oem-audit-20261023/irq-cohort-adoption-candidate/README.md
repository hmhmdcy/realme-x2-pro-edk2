# IRQ/cohort adoption after a real passed new boot

This source-only candidate completes the existing IRQ postboot chain. It does not deploy a module or boot image, issue charging controls, change desktop behaviour, accept physical latency or manufacture a current device identity. Actual use is after the separate Image502 adoption, successful three-file stage, boot-only IRQ activation and actual original-key IRQ postboot collection. None of those future actions was executed here.

`adopt.py::review(context, camera, probe, capture)` first reuses the frozen host R2's full saved-stage/activation/transport/raw-device audit. It then requires the exact new #502 UUID, IRQ boot `eddadec3…f6e06`, retained logdump `ace2e261…63ed1` and cohort manifest `5fca8e5a…9417`. The exact authenticated collection request and raw output hashes are retained. The capture belongs to this activation namespace. Previous software and hardware checks are reused rather than rerun in a new test matrix.

Explicit execution requires `--execute-adopt --window-confirmed` and the four actual evidence paths. Before creating its exclusive once directory, the caller checks the retained source502 global pointer against the activation's original adoption. The only remote code consists of the exact frozen read-only collector prefix plus the new adoption tail. A fresh complete raw audit and unchanged new UUID must pass again before a new mode0700 adoption directory is created. Proof is fsynced before the new UUID guard; both files are read back and both directory levels fsynced. A partial directory is retained and cannot be reopened. Existing guards are never written.

The host owns and waits the one original strict-key SSH Popen. Exact requested argv, stdin payload hash, observed /proc birth/cmdline and stdout/stderr are retained. WSL Windows interop may expose a different observed cmdline; requested and observed argv are retained separately and linked by that owned Popen. If child-receipt creation or input delivery fails, the owned stdin is closed to EOF and that same child is waited. There is no timeout kill, second launch or retry. A transport or receipt failure may leave a completed remote guard with an unpublished pointer; inspect the original result instead of replaying adoption.

Only after a successful fresh remote reply can the host publish its new endpoint and pointer. It checks the current global pointer against its original byte backup twice, writes a distinct temporary pointer, then atomically replaces and fsyncs it. This relies on the project's exclusive device-owner window; the two comparisons are not a general atomic compare-and-swap against an uncooperative concurrent writer. The old pointer backup and old guards remain available. A stale or changed pointer blocks publication.

Default execution only verifies software sources. Optimized Python is rejected. The 20 new tests run actual new review/guard/publish/transfer logic with synthetic identities and temporary files; the previously audited host and fresh device IO are explicit fakes at their established boundaries. One harmless local Linux child checks actual /proc birth capture; no SSH/USB endpoint is contacted. Fresh proof and UUID hashes, wrong boot/manifest/source pointer, partial-directory refusal, changed pointer, original-child receipt/input failure and same-child wait are covered. Existing host/device/operator suites were not rerun. These tests and a default source-only check passed; no actual request, guard, endpoint or transaction was created.

This tool's future success means software/current-boot adoption only. IRQ registration and charge state still need actual device verification, and fast physical plug/unplug response requires separately captured edges. It cannot turn offline tests into physical acceptance.
